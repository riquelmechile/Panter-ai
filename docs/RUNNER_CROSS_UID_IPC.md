# Issue #42 — Cross-UID read-only AF_UNIX contract

**Not deployed, and no grant/effect operations enabled.** The existing \`readonly_ipc.py\` server remains DENY-by-default: only \`runner.status\` can answer \`executionEnabled:false\`. This increment adds an explicit \`--socket-gid G\` mode for **different** runner and control-plane UIDs, rather than bypassing SO_PEERCRED or assuming chmod is enough.

- The server's effective UID owns the socket parent, its effective **primary GID equals G**, and the parent is exactly \`0710\` (owner rwx, group traversal only, others none). A symlink parent/ancestor and unknown or root GID fail closed. Existing default remains private parent \`0700\` and socket \`0600\`.
- When group mode is configured, the server creates a socket owned by the runner UID and group G with mode \`0660\` after binding, cleans up an occupied pathname only if it owns the inode, and still uses the kernel's \`SO_PEERCRED\` on EVERY connection before reading user-controlled bytes. Only the configured distinct \`--allow-uid\` may ask for read-only status. Another peer in the SAME group is DENIED by UID.
- The isolated GitHub-hosted Ubuntu **push-only** test runs as root only in that disposable CI VM, without useradd or a service installation. It forks a server as UID 65001/GID 65003 and clients as UID 65002 (allowlisted), UID 65004 (group member but not allowlisted), and UID 65004/GID 65005 (kernel permission denied). Test asserts owner/group/mode, authorized STATUS, forbidden release, rejected wrong UID, rejected non-member, and socket cleanup. Pull-request CI runs ordinary unprivileged unit tests; the privileged gate runs on a trusted in-repository push of the same SHA.
- **No production UID/group/ACL changes were made.** Numeric CI IDs and group do NOT prescribe Oracle UID values. After reviewer approval, an operator would separately have to provision dedicated principals and group policy, test independent witness identity and verify unit sandbox before any production operation.

The socket is still **only a status-only prototype**. It cannot receive or dispatch grants, verify live execution fencing or perform effects. This test is necessary but insufficient: cgroup termination/freeze, signed receipt binding, worktree security, grants anti-replay, fail-closed recovery, external R2/WORM and real-world E2E remain blocking. No deploy, Cloudflare, credentials, or Oracle changes.
